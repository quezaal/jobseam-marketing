Section 1

What each file is

Five HTML files and one PPTX in the jobseam-marketing/ folder. All HTML files are fully self-contained — screenshots, styles, and scripts are embedded — so they open in any browser with no server, no internet connection, and no dependencies.

File What it is Format Size Audience
jobseam-onepager.html Single-page sales overview. Features, ROI strip, multi-context comparison with live screenshots. First thing a cold prospect should see. HTML ~340 KB Cold prospects, warm intros
jobseam-deck.html 12-slide pitch deck in the browser. Problem, solution, platform features, market, traction, ask. For investor meetings and deep-dive prospect calls. HTML ~46 KB Investors, serious prospects
jobseam-deck.pptx Same deck as PowerPoint. Use for live screen-share presentations when you need slide control, or to email as an attachment. PPTX ~2 MB Live presentations
jobseam-video.html Full-screen animated player (19 scenes, auto-advance) + complete annotated walkthrough below. Every role, every feature, live screenshots. Your best "see it in action" link. HTML ~6 MB Anyone who wants to see the product
jobseam-feature-guide-detailed.html Complete feature reference: every filter, every column, every setting. Side-by-side screenshots of consulting vs. university context. For technical buyers who want to vet before committing to a demo. HTML ~350 KB Technical buyers, power users
jobseam-go-to-market.html Internal playbook: 30-day content calendar, YouTube script, channel tactics, outreach messaging. Not for prospects — this is your execution plan. Reference it daily. Internal ~54 KB Founder only (internal)
One rule for sharing
Never send all five files at once. Each material has a specific moment in the sales sequence. Sending everything upfront overwhelms prospects and removes your reason to follow up. See Section 4 for when to send what.
Section 2

Do you need dedicated hosting?

Short answer: no, not yet. The long answer depends on what you're hosting — the marketing pages are a completely different question from the product platform.

Marketing materials (the HTML files)
These are 100% static files. No database, no backend, no server process. A $0 GitHub Pages deployment gives you a permanent public URL in under 5 minutes. A VPS would be pure waste for this.
The JobSeam platform (for demos)
Currently running on Docker at localhost. For screen-share demos — Zoom, Google Meet — this is exactly right. You control the data, the environment, and the flow. No public access needed until you're ready to send "try it yourself" links.
The decision rule
Get to your first 3 paying customers with screen-share demos and static marketing pages. Then spend $6/month on a VPS (DigitalOcean, Hetzner) to run a live demo instance publicly. Custom domain costs $12/year. Nothing else is needed in year one.

Section 3

Where and how to publish each file

Step-by-step: getting URLs for every file using GitHub Pages. Do this once — then every update is a git push.

One-time setup: GitHub Pages

1
Create a GitHub repository. Go to github.com, create a new repo named jobseam-marketing. Set it to Public (required for free GitHub Pages).
2
Push the marketing folder. In your terminal:
cd /Users/jshaik/quezaal/jobseam-marketing
git init && git add *.html *.pdf *.pptx
git commit -m "Initial marketing materials"
git remote add origin https://github.com/jilani20/jobseam-marketing.git
git push -u origin main
3
Enable GitHub Pages. In the repo → Settings → Pages → Source: Deploy from a branch → Branch: main → folder: / (root). Click Save. Pages deploys in ~60 seconds.
4
Your URLs are live. Every file in the repo gets a URL at:
https://jilani20.github.io/jobseam-marketing/[filename].html
Save each URL — these are your shareable links for every campaign.
5
Optional: custom domain. In Pages settings, add marketing.jobseam.io or similar. Add a CNAME record at your DNS provider pointing to jilani20.github.io. Takes about 10 minutes. From then on, every file is at https://marketing.jobseam.io/[filename].html.

Section 4

How to use each material

Each file has a specific role in a specific moment of the funnel. Using the wrong material at the wrong moment either under-informs or overwhelms.

One-Pager
jobseam-onepager.html
Your broadest-reach asset. It answers "what does this do?" in under two minutes of reading. Use it as the first link you share with anyone — cold or warm. It has enough to create curiosity, not so much that it replaces a conversation.
When to send
Cold DMs, cold emails, LinkedIn post CTAs, after someone asks "what is this?"
What you say
"Here's a quick overview of what we've built: [link]. Happy to walk through it live if relevant."
Goal
Get a reply. Get them to book a demo. Not to close.
Video Walkthrough
jobseam-video.html
The highest-converting single asset you have. The full-screen player auto-plays and walks through the real product in 19 scenes with narration. The detailed annotated walkthrough below it covers every feature, every role, and every group context with actual screenshots. Send this when someone says "I'd like to see it before booking a call."
When to send
After initial interest, as YouTube description link, in post-demo follow-up, in LinkedIn posts as "watch it in action"
What you say
"Full platform walkthrough here — the player at the top auto-plays. Scroll down for annotated detail on every feature."
Goal
Self-serve demo. Book a live call for the 30% who want to talk after watching.
Pitch Deck (HTML)
jobseam-deck.html
Use the HTML version for async sharing — investors, advisors, and warm intros who want to review at their own pace. It loads in a browser and works on any device. The narrative arc is: problem → why now → solution → platform → market → traction → ask.
When to send
Investor intros, after discovery calls when prospect asks to share with their team, warm referrals
What you say
"Deck is here: [link]. Opens in a browser, no download needed."
Goal
Fundraise conversations. Warm up referrals who will forward to a prospect.
Pitch Deck (PPTX)
jobseam-deck.pptx
Use this for live presentations. Open in PowerPoint or Keynote before the call, share screen, and present slide-by-slide. You control the pace, you can skip slides based on the conversation, and you can add live annotations.
When to use
Zoom investor calls, in-person demo meetings, conference presentations
Tip
Keep slides 8–12 (platform features) ready but skip to what's relevant. Don't force all 12 in 30 minutes.
Goal
Drive to the "can I try it?" or "what does a pilot look like?" question by slide 10.
Feature Guide
jobseam-feature-guide-detailed.html
Your technical close asset. Send it after an intro call when someone says "I want to understand exactly what filters exist" or "how does the matching actually work?" It has the full filter list, every column, 2FA, AI pipeline details, and side-by-side screenshots from consulting vs. university contexts.
When to send
After discovery call, when prospect is evaluating seriously, to technical co-founder / CTO at a potential customer
What you say
"Full feature reference here — covers every filter, column, AI pipeline, 2FA, and group context. Let me know if anything is missing for your evaluation."
Goal
Remove objections before they become blockers. Answer "does it do X?" before it's asked.
The share sequence
Cold outreach → One-Pager link. They reply with interest → book a call. Pre-call → Video link. On call, share screen → PPTX deck. Post-call follow-up → Feature Guide if they're evaluating. Investor intro → HTML deck async.

Outreach LinkedIn DM Wave 1 follow-up: message 2 to those who opened but didn't reply. More specific — reference their firm size or market.

Outreach LinkedIn DM Wave 2: 50 new prospects. Adjust message based on Week 1 learnings. Target bench sales managers this wave (different angle from firm owners).
Video Record Video 2: live demo format. Pick a real vendor email, paste it into Req Inbox, show the AI extraction, run a match. No script — just the product working.

Outreach Wave 2 follow-up: message 2 to those who haven't replied. More specific insight. Offer the video link directly ("here's a 5-minute watch before we book time").
Outreach Start university outreach: 20 career services department heads at mid-size universities. Separate message track — lead with "placement-readiness" not "bench sales."
Day 14
Setup Week 2 review. How many demos ran? What objections came up? Update the pitch to address the top 2 objections before they surface next time. Note which materials people actually opened.
Week 3 · Days 15–21 · Proof Points + Scale
Day 15
Content "What we've seen in the data" post. Use real numbers from the live system: 22,000+ jobs indexed, N sources, average match time. Market data earns trust.
Demo Run demo batch 2 — university prospects from Day 13 outreach + anyone new from Wave 2.
Day 16
Outreach Wave 3: 50 new staffing firm prospects. This wave: target people who commented on industry posts (they're engaged, they're online now). Connection request + note, then DM if they accept.
Day 17
Content Individual user angle post: "You don't have to be a staffing firm to use this. If you're a consultant managing your own job search, there's a solo tier." Link to one-pager.
Day 18
Video Record Video 3: university context. Show the Students page, the cohort view, the placement-readiness breakdown. Fresh angle for a different audience.
Outreach Post-demo follow-up to Week 2 demos. "Any questions after reviewing? Happy to do a technical deep-dive if that helps." Offer feature guide link.
Day 19
Publish Upload Video 3 to YouTube. Share with the university audience specifically.
Demo First pilot conversation: for any prospect who attended 2 demos and asked detailed questions, move to "what does a 30-day paid pilot look like?" No free trials — a paid pilot validates intent.
Day 20
Outreach Community engagement: post something genuinely useful in the bench sales WhatsApp/Facebook groups. Answer a question someone asked. Build credibility before pitching in communities.
Day 21
Setup Week 3 review. Which channel drove the best conversations — LinkedIn content, direct DMs, communities? Double the best one in Week 4. Drop the worst one entirely.
Week 4 · Days 22–30 · Convert + Commit
Day 22
Content Post the content type that got the highest engagement in Weeks 1–3. Repeat the format, not the topic.
Outreach Warm leads re-engagement: anyone who opened a link, watched the video, or replied but went quiet. One more touch, with a new angle or data point.
Day 23–25
Demo Run all pending demo sessions. For each one: lead with the pain they described, not the product. Show the specific feature that solves their specific problem. Ask for pilot commitment at end.
Day 26–28
Outreach Wave 4 outreach based entirely on what worked. Same prospect profile as your best Wave 1–3 responses. Message based on what language got replies.
Content 2–3 more posts based on highest-engagement format from previous weeks.
Day 29–30
Setup 30-day retrospective. How many demos? How many pilots proposed? How many paying? Which marketing material was referenced most in conversations? Use this to plan Month 2.
Setup If you have even 1 paying pilot: write a one-sentence description of exactly who they are and what made them convert. That's your ICP. Build everything in Month 2 around finding more of them.
Section 6

When to host the platform itself

The marketing files are solved by GitHub Pages. The JobSeam platform — the Docker stack running at localhost — is a separate question. Here's how to think about it.

Stage Demo method Hosting needed Cost
First 0–10 demos Screen-share (Zoom, Meet). You run the app locally, share your screen. You control everything. None. Localhost is ideal — real data, full control, instant reset. $0
Prospects ask to try it themselves Self-serve trial access. They need a URL they can open independently. VPS with Docker. Deploy the full stack. One server, one environment. $6–$12/mo (DigitalOcean, Hetzner)
Multiple pilots running concurrently Each customer needs their own group and data isolation. Same VPS works for 3–5 groups. Add more resources when needed. Still no dedicated infra required. $12–$24/mo
First paying tier Production environment. Customers expect uptime and backups. Two servers: app + database, or managed Postgres (Supabase/Neon). Set up backups. Add SSL certificate (free with Let's Encrypt). $20–$40/mo
Recommended path for the platform

When your first prospect says "can I log in and try it myself?" — that's the trigger. Not before. Set up a $6/mo DigitalOcean droplet, deploy the Docker Compose stack, add a free SSL cert with Certbot, create a demo group for them. Total setup time: 2–3 hours.

Use Hetzner (€3.79/mo) if cost matters more than location. Use Railway or Render if you want the platform managed (no SSH required, ~$20/mo). Railway in particular supports Docker Compose and deploys from GitHub.

Don't do this before you need it
Setting up hosted infrastructure before you have a prospect asking for self-serve access is a distraction. Every hour spent on DevOps is an hour not spent on the 3 conversations that could get you your first paying customer. Screen-share demos close deals. Perfect uptime does not.

Quick-reference: what to set up and when

  • Today (pre-launch): GitHub Pages for marketing files. That's it.
  • When the first prospect asks for a self-serve trial: DigitalOcean droplet ($6/mo), Docker Compose up, Certbot SSL, one demo group created.
  • When you have 3+ concurrent pilots: Add a second droplet for Postgres, or move to managed Postgres (Supabase free tier is fine). Set up daily backups.
  • Custom domain for the platform: app.jobseam.io — buy the domain when you buy it for the marketing site ($12/yr total, covers both).
  • What you never need in year one: Kubernetes, dedicated servers, CDN for the app, multi-region deployment. Build those when you have customers who need them.
